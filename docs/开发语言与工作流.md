# 开发语言与工作流
### ROCK 5B+ 上用什麼语言写、代码怎么跑起来

---

## 一、一句话答案

**板子上用 Python 3，ESP32 上用 Arduino C++，启动脚本用 Shell。**

就这三种，不需要学 C/C++ 系统编程。

---

## 二、语言分工

想想你的作品架构：

```
[麦克风] → USB声卡 → ROCK 5B+ ─┬─→ 变声处理 → USB声卡 → [耳机/音箱]
                                └─→ Python 串口
                                       ↓ USB
                                   ESP32 (Arduino C++) → WS2812B 灯带
```

| 环节 | 语言 | 为什么用它 |
|---|---|---|
| **板子上的一切**<br>（音频、变声、AI、串口、显示） | **Python 3** | 库最全：`numpy` / `sounddevice` / `pyserial` / `sherpa-onnx` / `luma.oled`。零基础出活最快 |
| **ESP32 灯效** | **Arduino C++**<br>（FastLED / NeoPixel 库） | Arduino 生态对零基础最友好，例程最多，灯效代码网上到处是 |
| **一键启动** | **Shell (.sh)** | 演示时一条命令拉起全部 |
| 性能优化 | ~~C / C++~~ | **用不上**。你的瓶颈是 NPU 和音频延迟，不是 Python |

### 为什么是 Python 而不是 C++

- **AI 生态在 Python 上最全。** `sherpa-onnx`、`onnxruntime` 的第一等公民都是 Python
- **瓶颈不在语言。** 6 TOPS 的 NPU 推理和音频 I/O 延迟才是关键，Python 的调用开销可以忽略
- **零基础。** C++ 在 ARM 上交叉编译、链接 ALSA 库，够你耗掉两周

**结论：这个项目完全不需要写 C++。** 唯一会碰的"非 Python"就是 ESP32 那边的 Arduino 代码。

## 三、开发流程：一条最重要的原则

> ## ⭐ 在笔记本上写代码，在板子上跑

**不要用 `nano`/`vim` 在 SSH 里直接写代码。** 没有显示器、只有终端，改错一个字符就要重来，效率极低。

正确的方式是：

```
笔记本（VS Code）编辑 → 文件实际存在板子上 → 板子上运行 → 看输出 → 改
```

---

## 四、工具链：VS Code + Remote-SSH（强烈推荐）

这是这个项目最值得花 30 分钟配置的东西。

1. 笔记本装 **VS Code**
2. 装扩展 **Remote - SSH**
3. `F1` → `Remote-SSH: Connect to Host` → 输入 `radxa@<板子IP>`
4. 连上后，VS Code 左侧就是**板子的文件系统**，编辑起来和本地一模一样
5. `Ctrl+`` ` 打开内置终端，**这个终端就在板子上**，直接 `python3 xxx.py` 运行
6. Python 补全、跳转、语法检查全都能用

**好处**：你用的是笔记本的大屏幕、熟悉的环境、完整的编辑器能力，但文件一直在板子上，改完直接跑，**没有同步这一步**。

### 备选方案

| 方案 | 适用场景 |
|---|---|
| `scp` / `rsync` 手动传 | 偶尔传单个文件 |
| **git + GitHub** | ⭐ **三人协作时用这个**——各写各的分支，避免互相覆盖 |
| VS Code Remote-SSH | 日常开发的主力 |

> **不要**在板子上装 VS Code 的 ARM64 版——没显示器，而且跑起来很慢。

## 五、Python 环境：必须用 venv

Debian（Radxa OS 的基础）启用了 PEP 668，**直接 `pip install` 会报 `externally-managed-environment` 错误**。正确做法：

```bash
sudo apt update
sudo apt install -y python3-venv python3-pip
mkdir -p ~/proj && cd ~/proj
python3 -m venv venv
source venv/bin/activate          # ← 每次开新终端都要执行这句
pip install numpy sounddevice pyserial
```

- ⚠️ **绝对不要用 `sudo pip install`** —— 会污染系统 Python，后面极难收拾
- 提示符前面出现 `(venv)` 就说明激活成功
- 装 `sherpa-onnx` 时也一样，在 venv 里装

## 六、代码结构建议

```
~/proj/
├── venv/              # 虚拟环境（不用管）
├── main.py            # 主程序：串起所有环节
├── audio.py           # 录音 / 放音（sounddevice）
├── voice.py           # 变声算法（numpy：环形调制 / 移调）
├── ai.py              # 语音识别控灯（sherpa-onnx）
├── leds.py            # 通过串口给 ESP32 发灯效数据
├── config.py          # 所有参数集中在这（音色、灯效、设备号）
├── start.sh           # 一键启动（演示时用）
└── 开发日志.md         # 每天 3 行，最后直接整理成报告
```

**把参数集中在 `config.py`** —— 演示现场要临时改音量、灯效、设备号时，你只需要改一个文件。

## 七、三人如何协作（一块板子）

| 角色 | 主要语言 | 干什么 |
|---|---|---|
| **A · 硬件线** | **Arduino C++** | 灯带、ESP32、供电、亚克力道具 |
| **B · 软件线** | **Python** | 系统、音频、变声、AI |
| **C · 支撑线** | **Shell + Markdown** | 采购、开发日志、测试、演示编排 |

**协作要点：**

1. **代码用 git 管**，各写各的分支。三个人同时改一个文件必然互相覆盖
2. **终端用 tmux 共享**（见 `无显示器方案_串口与远程.md`），一个人操作、另两人围观
3. **板子只有一个**，用 SSH 多会话，别三个人抢着改

```bash
sudo apt install -y tmux
tmux new -s work      # 第一个人创建
tmux attach -t work   # 另两人 attach
```

## 八、新手必踩的 6 个坑

| # | 坑 | 解决 |
|---|---|---|
| 1 | `sudo pip install` | ❌ 永远不要。用 venv |
| 2 | `externally-managed-environment` 报错 | ✅ 因为没激活 venv |
| 3 | **串口打不开** `/dev/ttyUSB0` 权限不足 | `sudo usermod -aG dialout radxa`，然后**重新登录**（这是最高频的坑） |
| 4 | **硬编码音频设备号** `plughw:1,0` | ⚠️ 数字会随插拔顺序变。用 `sd.query_devices()` 查，别写死 |
| 5 | `start.sh` 找不到文件 | 脚本里**全部用绝对路径**；`cd` 到脚本所在目录再执行 |
| 6 | 忘了 `source venv/bin/activate` | 症状是"明明装了却 import 不到" |

## 九、开发循环长什么样（结合六关路线）

| 阶段 | 你实际在做什么 | 语言 |
|---|---|---|
| **第 0 关** | 烧系统、SSH 连上、装 VS Code Remote-SSH | Shell |
| **第 1 关** | 先跑 `arecord`/`aplay` 验证，再写最小 Python 录音放音脚本 | Shell → **Python** |
| **第 2 关** | 变声算法（先在笔记本上验证，再上板子） | **Python** |
| **第 3 关** | ESP32 灯效（**独立开发，不依赖板子**） | **Arduino C++** |
| **第 4 关** | 板子 serialize ↔ ESP32 收数据 | **Python** + **Arduino C++** |
| **第 5 关** | sherpa-onnx 语音识别控灯 | **Python** |
| **第 6 关** | （冲刺）神经变声 | Python |

**注意第 3 关**：灯效可以在笔记本 + ESP32 上独立做完，**完全不等板子**。这是三人可以并行的关键。

## 十、要不要学 Linux？

**要，但只需要很少一点。** 你实际会用到的命令基本就这些：

```bash
cd / ls / mkdir / cp / mv / rm        # 走动
apt install / apt update               # 装软件
python3 xxx.py                         # 跑程序
sudo systemctl restart xxx             # 重启服务
chmod +x start.sh                      # 给脚本执行权限
tail -f log.txt                        # 实时看日志
```

**不需要**学 shell 脚本编程、系统编程、内核、交叉编译。遇到不会的随时问就行。

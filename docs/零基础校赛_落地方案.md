## 第一部分：先把项目范围定对（这一步比买什么更重要）

### 你原定的目标 vs 现实

| 目标 | 零基础可行性 | 建议 |
|---|---|---|
| **屏幕显示效果**（频谱 / 波形 / 图片） | ✅ 完全可行，一周内能出效果 | 作为**主线**，做扎实 |
| **AI 变声** | ⚠️ 分两种：<br>「实时变声器」（移调/机器人音）= 3 天能做<br>「真·AI 神经变声」（RVC/so-vits-svc 跑 NPU）= 数周，成功率低 | 先做前者保底，后者当冲刺 |

**真·AI 变声为什么对零基础很难**：不是算力问题（RK3588 的 6TOPS NPU 够），而是①要把 PyTorch 模型转成 RKNN 格式，而这个转换工具**只能在 x86 Linux 上跑**；②要做实时流式推理 + 低延迟音频管道。这两件事各有大量坑，不适合当主线。

### 强烈推荐的重新定位：**「会听会变声的智能终端」**

把两个题目**合成一个作品**，因为它们共用同一条音频通路：

```
麦克风 → USB声卡 → ROCK 5B+ ─┬─→ 变声处理 → 耳机/音箱      【听得出的效果】
                              └─→ 频谱/波形分析 → SPI 屏    【看得见的效果】
                                   （1.54" ST7789 直连，无额外控制器）
```

**为什么这样设计对零基础特别友好：**
1. **一份硬件，两个功能**，预算不翻倍。
2. **保底和冲刺分离**：屏幕显示做成了就一定能演示；变声做成了再叠加；AI 语音识别做成了再叠加。**任何一层没做完，作品都还是完整的。**
3. **演示效果强**：说话时屏幕上频谱随声音跳动 + 变声，视觉听觉双冲击，评委印象最深。**而且频谱能直接展示"变声改变了频率分布"这件事**——这是灯带做不到的。
4. 答辩故事线清晰：「输入（声音）→ 处理（实时算法/AI）→ 输出（变声 + 屏幕可视化）」。

## 第三部分：两个关键技术选型（解释为什么这么配）

### 选型 1：为什么用 **SPI 屏直连**，而不是 ESP32 + 灯带

**原方案**是「ROCK → 串口 → ESP32 → WS2812B 灯带」，**已放弃**。直接原因是赛方规则：

> **原规则**：「必须使用赛方提供的主控（ROCK 5B+），其余主控不得分。」
>
> **我们的提问**：ESP32 只作为灯带驱动执行器（接收 5B+ 指令并驱动灯带）是否算"其他主控"？
>
> **赛方原话答复**：
> > 「可以加，但是主要代码还是要跑在 rock 上」

虽然拿到了"可以加"的许可，但 ESP32 上必然要跑灯效渲染代码，**相当于第二份程序**，答辩时仍有解释成本。

**改用 1.54" SPI 屏直连之后的对比：**

| | ESP32 + 灯带（原方案） | **SPI 屏直连（现方案）** |
|---|---|---|
| 额外可编程芯片 | ESP32（一颗） | **无** ✅ |
| 代码分布 | Python + Arduino C++ | **100% Python** ✅ |
| 通信协议 | 要自己设计串口帧格式 + 校验 | SPI 是标准接口，**不需要协议** ✅ |
| 视觉表现 | 只能表达亮度 / 颜色 / 节奏 | **频谱 / 波形 / 文字 / 图片** ✅ |
| 显示决策在哪 | 要分一部分给 ESP32 | **全部在 ROCK 上** ✅ |
| 调试复杂度 | 两个设备、两套工具链 | 一个进程 ✅ |

**而且屏幕能做灯带做不到的事**：把"**变声改变了频率分布**"直接画出来给评委看——
切到女声时高频段亮起、低频段暗下，这是**一眼就能看懂的技术展示**。

> 接线表、驱动方案、频谱算法、性能架构、故障排查 → 见 **[`屏幕显示子系统.md`](屏幕显示子系统.md)**

### 选型 2：SPI 屏为什么**不需要**电平转换

屏幕模块工作电压 **2.5–3.3V**、逻辑电平 **3.3V**，而 ROCK 5B+ 的 40-pin GPIO **也是 3.3V**。

**天然匹配，不需要任何电平转换。** 原方案里的 74AHCT125 是为了让 3.3V 驱动 5V 灯带，现在**整个取消**。

> ⚠️ 但同一条 3.3V 规则反过来是个大坑：**绝不能把 5V（Pin 2/4）接到屏幕的 VCC**。
> 这款屏只支持 2.5–3.3V（很多别的 1.54" 模块支持 5V，这款不支持），接错可能直接烧掉。

### ⚠️ 显示子系统最大的技术风险：性能

屏幕每帧 **240×240×2 = 115 KB**，SPI 40MHz 下单帧传输约 **23 ms**（上限约 43fps，实测 20–30fps）。
而**音频处理必须实时，绝不能被屏幕刷新拖住**。

**必须用「音频线程 + 只保留最新帧的队列 + 显示线程」的三段式架构**：

```
音频回调（≈5ms 一块，只做采集/变声/播放 + 算 RMS/FFT）
   → Queue(maxsize=1)：满了丢旧数据（关键！否则显示延迟越积越大）
   → 显示线程（25 fps）：渲染整帧 → SPI 推屏
```

详细实现要点见 `屏幕显示子系统.md` 第 5 节。

### 供电：继续用你的 HD-05，但守纪律

Radxa 官方文档《Power Board Via 40 PIN GPIO》**正是拿 ROCK 5B+ 举例**，明确该路径**最大 25W**，且电压必须稳定在 5.0–5.2V（[来源](https://docs.radxa.com/en/rock5/rock5b/hardware-design/power_board_from_40pin)）。你的 HD-05 是 5V/5A = 25W，正好卡上限。

- **接法**：5V 接 **Pin 2 + Pin 4 各一根**；GND 接 **Pin 6/9/14/20**（多接几根）；线用 22AWG 或更粗
- **上电前先用万用表量空载电压**，超 5.2V 会烧板
- **纪律**：不装 NVMe、不装 4G、不接移动硬盘；**音箱用独立电源，绝不从板子取电**（屏幕只吃 30–50mA，从 40-pin 的 3.3V 取电没问题）
- **25W 够不够？** 官方说 40W 是因为"两块 SSD + 4G 模块"额外耗电。你只从 microSD 启动 + 一个 USB 声卡，25W 够用
- **唯一的硬约束**：跑压力测试，一旦掉电重启，立刻买 65W PD 充电器（¥60）

> 散热不用管：**AE013B = Radxa Heatsink 6240B，自带 7000RPM 风扇**（2-Pin 1.25mm / 5V），接到板子 FAN 口，在 `rsetup` 里把 thermal governor 设成 `power_allocator` 就行。

## 第四部分：六关路线图（每关都有明确的验收标准）

> 每一关都以「能验证的现象」结尾。**卡住超过一天就在群里问，别自己死磕。**

### 第 0 关：把板子点起来（1–2 天）

1. 下载 **ROCK 5B+ 专用** Debian 镜像（⚠️ 不是 ROCK 5B 的，两者镜像不通用）
2. 用 balenaEtcher / Raspberry Pi Imager 写入 microSD
3. 插 HDMI + USB 键盘，或插网线后从路由器后台找 IP，然后 SSH
4. ✅ **验收：看到桌面，或 `ssh radxa@<IP>` 登录成功**（默认密码 `radxa`）

**新手坑**：杂牌 SD 卡是"板子点不亮"的头号原因，**一定买正品 A2**。首次启动可能会自己重启一两次（自动扩容分区），别慌。

### 第 1 关：让板子能录音、能放音（1–2 天）

```bash
arecord -l        # 找到 USB 声卡的 card/device 号
aplay -l
alsamixer         # 选对声卡，按 M 键取消静音，Mic 增益调上去  ← 90% 的人卡在这
arecord -D plughw:1,0 -f S16_LE -r 48000 -d 5 test.wav
aplay -D plughw:1,0 test.wav
```
✅ **验收：录下自己的声音并能回放出来**

> 备选：板载 3.5mm 是耳麦二合一口（ES8316），要先用四段 CTIA 耳麦，并执行 `sudo amixer -c 1 cset numid=2 1` 开启录音。但**很容易踩坑，优先用 USB 声卡**。

### 第 2 关：做出「能变声」的效果（2–4 天）

**方案 A（推荐，最可靠）**：Python + `sounddevice` + `numpy`
- **机器人音**：把信号乘一个正弦波（环形调制），约 10 行代码，效果明显又稳定
- **升/降调**：改变重采样率实现移调

**方案 B（一行命令）**：
```bash
sox -t alsa plughw:1,0 -t alsa plughw:1,0 pitch 400    # 升调，萝莉音
sox -t alsa plughw:1,0 -t alsa plughw:1,0 pitch -400   # 降调，大叔音
```
✅ **验收：戴耳机对着麦说话，耳机里出来的是变调的声音，延迟能接受**

**这就是你的保底交付物。** 一个实时变声器本身就是合格的作品，别觉得它不够"AI"。

### 第 3 关：点亮 SPI 屏（2–3 天）

> ⚠️ **这一关的性质和原方案不同**：屏幕必须接在板子上（SPI 在 40-pin），**不能再像灯带那样在笔记本上独立开发**。

1. **在板子上打开 SPI 覆盖**：`sudo rsetup` → **Overlays → Manage overlays** → 启用 `spi0-m2-cs0-spidev` → 重启
2. 验证：`ls -l /dev/spidev*` 出现设备节点
3. 装依赖：`sudo apt install -y python3-libgpiod python3-spidev python3-pil`
4. 先填纯色 → 再填渐变 → 再画一条色带
5. ✅ **验收：屏幕上能显示纯色和渐变**

**新手坑清单**（照这个顺序查）：
- 全黑但背光亮 → 初始化序列不对；`RES` 没接或没复位
- 全黑且背光也不亮 → `BLO` 没接 3.3V；或 `VCC`/`GND` 接反
- 白屏 → `DC` 或 `CS` 接错（命令和数据没分开）
- 花屏 / 雪花 → **SPI 速率太高**或杜邦线太长 → 先降到 10MHz，稳定后再往上提
- 红蓝互换 → RGB / BGR 顺序设置不对

> 💡 **补偿办法（保住并行开发）**：把渲染函数写成"**输出一张 PNG**"，用假数据在笔记本上跑，
> 直接看图片验证布局和配色——**不需要屏幕、也不需要板子**。只有最后一步推屏才需要硬件。

### 第 4 关：音频线程 → 队列 → 显示线程（1–2 天）

- **音频线程**：`sounddevice` 回调**只做**采集 / 变声 / 播放，顺便算 RMS 与 FFT
- **队列**：`Queue(maxsize=1)`，**满了丢旧数据**（不丢的话显示延迟会越积越大）
- **显示线程**：25 fps 取最新数据 → 渲染整帧 → SPI 推屏
- ✅ **验收：在板子上改一个数字，屏幕上频谱的高度跟着变**

> ⚠️ **铁律：显示线程绝不能阻塞音频回调。** 一旦阻塞，音频立刻爆音/卡顿。

### 第 5 关（强烈建议做）：「AI 卖点」—— 频谱做好看 + 语音控制显示

**5a. 把频谱做"好看"（半天，纯数学但视觉冲击最大）**

四个要点，缺一个都会显得廉价：

| # | 要点 | 不做会怎样 |
|---|---|---|
| 1 | **对数频率轴** | 线性分段时 16 根柱子有 14 根是空的 |
| 2 | **汉宁窗** | 频谱泄漏，柱子之间互相串色，看起来糊 |
| 3 | **转 dB** | 人耳是对数的，线性幅度下弱频段完全看不见 |
| 4 | **平滑下落** `bars = max(bars*0.75, new)` | 柱子每帧乱跳，视觉上很廉价 |

（详见 `屏幕显示子系统.md` 第 6 节）

**5b. 语音关键词识别（1 周，真正的 AI）**
```bash
pip install sherpa-onnx
```
`sherpa-onnx` **提供 Linux ARM64（aarch64）的预编译包**，在 ROCK 5B+ 上可以直接 `pip` 装，并且原生支持**关键词识别（KWS）、语音活动检测（VAD）、语音识别（ASR）**，还支持 **Rockchip NPU（RKNN）**（[PyPI 页面](https://pypi.org/project/sherpa-onnx/)）。

玩法：说「换照片」→ 屏幕切图；说「关屏」→ 熄灭背光。或者用 VAD：检测到你在说话 → 屏幕进入"聆听"状态。
✅ **验收：说一个词，屏幕正确响应**

> **这就是你作品里最有说服力的 AI 部分** —— 离线、本地运行、看得见效果、零基础两周内可完成。比硬啃神经变声划算得多。

### 第 6 关（冲刺，高风险，别当主线）：真·神经变声

**先分清两条路，难度差一个数量级：**

| | 实时 AI 变声 | ⭐ 离线 AI 变声（推荐） |
|---|---|---|
| 做法 | RVC 流式推理，边说边变 | 录 10 秒 → 转成另一个音色 → 播放 |
| 要不要 RKNN 转换 | **要**（PyTorch→ONNX→RKNN，几周工作量） | **不要**（直接装 PyTorch CPU 版跑原版） |
| 难度 | ★★★★★ | ★★★ |

**离线版为什么可行**：离线转换对速度没要求，所以完全不需要碰 NPU 转换工具链——在板子上 `pip install torch`（aarch64 有现成 wheel）跑原版 RVC 推理，慢 30–60 秒无所谓。演示效果依然震撼。

**实时版需要**：一台 x86 Linux（WSL2 / Ubuntu）装 `rknn-toolkit2` → 转模型 → 流式推理优化。RVC 的生成器有自定义算子和动态 shape，RKNN 支持有限，可能要改结构。**公开成熟的"RK3588 实时 RVC"项目我没找到，这个"找不到"本身就是强信号。**

**决策规则**：**11/1 闸门 2 之后，如果第 5 关已稳、还有余力，先做离线版。实时版基本可以放弃——11/5 闸门 3 起进入代码冻结，只排练不加功能。**

## 第五部分：演示设计（校赛拿分的关键）

零基础队伍和强队的差距，往往不在技术，而在**演示是否顺畅、故事是否讲得清**。

### 做一个「道具」
把麦克风、屏幕、亚克力面板做成一体的东西——比如一个**带频谱显示的立牌**或**小型终端**。散着一堆开发板和飞线，观感直接掉一档。

**屏幕尺寸参考**：1.54"（显示区 30×31mm），模块 32×38.5mm，**安装孔 φ2mm / 孔距 28mm** —— 有现成固定孔，做道具很方便。

### 演示脚本（控制在 3 分钟）
1. **开场**：说一句话，屏幕上的频谱随声音跳动 →「这是实时音频可视化，全部在本机运算」
2. **变声**：按下切换，同一句话变成另一种音色 →「这是实时变声，全部在这块板子上跑」
   - 💡 **这里是最强的技术展示点**：切到女声时，**屏幕上的频谱整体右移**（高频亮起、低频暗下）。
     可以直接对评委说：「**看，频率分布变了——这就是变声的本质**」。**这是灯带做不到的。**
3. **AI 交互**：说「换照片」→ 屏幕切图 →「这是本地离线语音识别，不联网」
4. **收尾**：「整套系统只用了一块 ROCK 5B+，**没有任何额外的控制器**；输入是声音，输出是声音和画面」

### 务必提前排练
- 至少完整彩排 5 遍，包括**断电重启后能不能一键启动**
- 写一个 `start.sh` 把变声和显示一起拉起来
- **带上备用 microSD 和那 ¥60 的 PD 充电器**——现场最容易出问题的就是供电和存储

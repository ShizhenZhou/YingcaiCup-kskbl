# 开发环境配置
### Windows 11 + VS Code + Python 3.12 的电脑，怎么把整套配起来

---

## ⚠️ 先看最重要的一条

**如果你的 Python 是 3.14，装不了 `rknn-toolkit2`。**（本项目已确认统一用 **3.12**，两条链路都满足。）

这是 Radxa 官方文档给出的版本兼容矩阵（[RKNN 安装](https://docs.radxa.com/rock5/rock5t/app-development/ai/rknn-install)）：

**x86 PC 上做模型转换（RKNN-Toolkit2）：**

| 操作系统 | 支持的 Python 版本 |
|---|---|
| Ubuntu 18.04 x64 | 3.6 / 3.7 |
| Ubuntu 20.04 x64 | 3.8 / 3.9 |
| Ubuntu 22.04 x64 | **3.10 / 3.11** |
| Ubuntu 24.04 x64 | 3.12 |

**ARM64 板端做推理（rknn-toolkit-lite2）：**

| 操作系统 | 支持的 Python 版本 |
|---|---|
| Debian 10 arm64 | 3.6 / 3.7 |
| Debian 11 arm64 | 3.8 / 3.9 |
| Debian 12 arm64 | **3.10 / 3.11 / 3.12** |

**Python 3.14 不在任何一格里。**

**好消息**：`rknn-toolkit2` 只在**第 6 关（神经变声）**才需要。而你们的主线（变声 DSP + 灯效 + 语音识别）完全不受影响——`sherpa-onnx` 已经提供 cp314 的 wheel 了。

**结论：本项目统一用 Python 3.12**——它同时落在 PlatformIO 和 RKNN 两条链路的支持范围内，一个版本通吃。

---

## 你要配的是 4 个独立环境

| 环境 | 在哪 | Python 版本 | 用途 | 什么时候需要 |
|---|---|---|---|---|
| **A. Windows** | 你的笔记本 | **3.12 ✅ 已装**（D:\Program Files\Python312） | 算法原型、VS Code 连板子、烧 ESP32 | **今天就能配** |
| **B. 板子** | ROCK 5B+ | **3.11**（Debian 12 自带） | 跑项目主体 | SD 卡到货后 |
| **C. WSL2** | 笔记本里 | **3.10 / 3.11**（conda 建） | 模型转换 | 只在第 6 关 |
| **D. ESP32** | 开发板 | —（Arduino C++） | 灯效固件 | 第 3 关 |

**⚠️ 关键：不要试图把这几个环境的 venv 互相复制。** 架构不同（x86 vs ARM64）、Python 版本不同，各自独立建。

---

## 第 1 步：Windows 侧（今天就能做完）

### 1.1 装 VS Code 扩展

**先看你已有什么**（实测结果）：VS Code **1.138.0**，已装 `ms-python.python`、`ms-python.vscode-pylance`、`ms-python.debugpy`、`ms-vscode.cpptools`、中文语言包 —— **Python 和 C/C++ 都不用再装**。

| 需要装 | 扩展 ID | 用途 | 必需 |
|---|---|---|---|
| **Remote - SSH** | `ms-vscode-remote.remote-ssh` | 连板子开发 | ⭐ **必需** |
| **PlatformIO IDE** | `platformio.platformio-ide` | 写 ESP32 固件（**替代已弃用的 Arduino 扩展**） | ⭐ **必需** |
| Serial Monitor | `ms-vscode.vscode-serial-monitor` | 看 ESP32 串口输出 | 推荐 |
| Wokwi Simulator | `wokwi.wokwi-vscode` | 不接硬件仿真 ESP32 + WS2812B | 推荐 |

```powershell
code --install-extension ms-vscode-remote.remote-ssh
code --install-extension platformio.platformio-ide
code --install-extension ms-vscode.vscode-serial-monitor
code --install-extension wokwi.wokwi-vscode
```

> **⚠️ 不要装 `vsciot-vscode.vscode-arduino`。** 官方 `package.json` 里它的 `displayName` 直接写着 **"Arduino (deprecated)"**，`description` 是 "This extension is deprecated and no longer maintained."，版本停在 0.7.1。**用 PlatformIO 代替。**

> **版本说明**：VS Code 1.138.0 很新，上面四个扩展**都能装最新版，不存在需要降级的情况**。
> 唯一有点滞后的是中文语言包（停在 1.131，而 VS Code 已 1.138）——建议顺手更新一下。

> **✅ 已解决**：本机原先只有 Python 3.14，PlatformIO 建环境时会踩坑。现已改装 **Python 3.12**（`D:\Program Files\Python312`），同时满足 PlatformIO 与 RKNN 两条链路。
> 实在搞不定就退回 **Arduino IDE 2.x 独立软件**——它自带一切、不需要 Python，对零基础反而更省事。

### 1.2 建一个原型用的 venv

```powershell
mkdir $HOME\proj
cd $HOME\proj
py -3.12 -m venv .venv
.\.venv\Scripts\Activate.ps1
pip install numpy sounddevice
```

### 1.3 ⚠️ 别忘了开 Windows 麦克风权限

**设置 → 隐私和安全性 → 麦克风 → 打开「允许桌面应用访问麦克风」**

不开的话 `sounddevice` 拿不到任何输入设备，你会以为程序写错了。

### 1.4 验证

```powershell
python -c "import sounddevice as sd; print(sd.query_devices())"
```

**能列出设备列表就说明 Windows 侧配好了。** 顺便记下你笔记本麦克风的设备号，先在 PC 上把变声算法跑通。

### 1.5 配 SSH 免密（可选但强烈建议）

省掉每次输密码：

```powershell
ssh-keygen -t ed25519
type $env:USERPROFILE\.ssh\id_ed25519.pub | ssh radxa@<板子IP> "mkdir -p ~/.ssh && cat >> ~/.ssh/authorized_keys"
```

## 第 2 步：板子侧（SD 卡到货、第 0 关之后）

板子是 **Debian 12（bookworm）**，自带 **Python 3.11**——正好在 RKNN 支持范围内。**不要动系统 Python。**

```bash
sudo apt update
sudo apt install -y python3-venv python3-pip

mkdir -p ~/proj && cd ~/proj
python3 -m venv venv
source venv/bin/activate          # ← 每开一个新终端都要跑这句
pip install numpy sounddevice pyserial
```

⚠️ **绝对不要 `sudo pip install`** —— 会污染系统 Python，后面极难收拾。

> Radxa 官方也有专门文档：[Python 虚拟环境使用](https://docs.radxa.com/rock5/rock5t/app-development/venv_usage)

---

## 第 3 步：VS Code 连上板子（核心）

1. `F1` → `Remote-SSH: Connect to Host` → 输入 `radxa@<板子IP>`
2. 首次连接会问平台，选 **Linux**
3. 连上后 `Ctrl+`` ` 打开终端 —— **这个终端就在板子上**
4. 在左侧文件树里打开 `~/proj`，直接编辑板子上的文件

**从此刻起：编辑在笔记本，执行在板子，没有"同步"这一步。**

> Radxa 官方文档：[VS Code Remote SSH 开发](https://docs.radxa.com/rock5/rock5t/app-development/vscode-remote-ssh)

**记得在板子的终端里先 `source venv/bin/activate`**，否则 VS Code 的 Python 补全指向系统 Python，会报"找不到 numpy"。

---

## 第 4 步：WSL2 + conda（只在第 6 关需要）

**现在别装，等做到第 6 关再说。** 到时候：

```powershell
wsl --install -d Ubuntu-22.04
```

然后在 WSL 里装 Radxa 官方推荐的 **Miniforge**：

```bash
# 官方推荐用 conda 管理 RKNN 的 Python 环境
wget https://github.com/conda-forge/miniforge/releases/download/25.11.0-0/Miniforge3-25.11.0-0-Linux-x86_64.sh
chmod +x Miniforge3-25.11.0-0-Linux-x86_64.sh
bash Miniforge3-25.11.0-0-Linux-x86_64.sh

conda create -n rknn python=3.10     # ← Ubuntu 22.04 对应 3.10/3.11
conda activate rknn
```

**为什么用 conda 而不是 venv**：conda 能装任意版本的 Python，venv 只能用系统已有的。Ubuntu 22.04 系统 Python 是 3.10，够用；但 conda 更灵活。

---

## 第 5 步：ESP32 侧（可以和板子完全并行）

这部分**不依赖 ROCK 5B+ 和 SD 卡**，是你们现在唯一能立刻动手的。

1. VS Code 装 **Arduino** 扩展
2. 在 Arduino 扩展里装 **esp32 开发板支持包**
3. 装库：**Adafruit NeoPixel** 或 **FastLED**
4. ESP32 用 USB 插笔记本 → 选对板型和串口 → 点上传

**⚠️ 一个流程上的关键点**：ESP32 只有一根 USB 线。

- **开发灯效时**：插笔记本（才能烧录）
- **演示时**：插板子（板子要通过串口给它发颜色数据）

**所以灯效调好后要"搬家"**：从笔记本拔下来插到板子上。要改灯效就再搬回来。

**规避办法**：把所有灯效模式都先在 ESP32 里写全，板子只发一个"模式编号"（1 个字节），这样后期基本不用重烧。

## 验证清单

配完对着这个表核一遍：

| # | 检查项 | 命令 / 操作 | 通过标准 |
|---|---|---|---|
| 1 | Windows venv | `python -c "import numpy, sounddevice"` | 无报错 |
| 2 | Windows 麦克风 | `sd.query_devices()` | 列出设备 |
| 3 | SSH 免密 | `ssh radxa@<IP>` | 直接进去 |

**第 9 项是变声的核心链路，通了就可以开始写算法了。**

## 常见问题速查

| 症状 | 原因 | 解决 |
|---|---|---|
| **`python3` 弹出 Microsoft Store** | Windows 的 Store 应用别名（0 字节存根）抢占了 `python3` | 用 `python` 或 `py` 代替；或去「设置 → 应用 → 高级应用设置 → **应用执行别名**」关掉 `python.exe` / `python3.exe` |
| `externally-managed-environment` | 没激活 venv | `source venv/bin/activate` |
| VS Code 里 import 报错但终端正常 | VS Code 选错了解释器 | `Ctrl+Shift+P` → Python: Select Interpreter → 选 venv 里的 |
| `/dev/ttyUSB0` 打不开 | 不在 dialout 组 | `sudo usermod -aG dialout radxa` 然后**重新登录** |
| 找不到麦克风 | Windows 权限 / ALSA 静音 | 开权限；板子上 `alsamixer` 按 `M` 取消静音 |
| Remote-SSH 连不上 | 板子 IP 变了 / SSH 没开 | 串口里 `ip a` 重新查 |

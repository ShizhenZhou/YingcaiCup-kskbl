# 存储需求评估
### 「简单 AI 语义理解控灯」+「简单实时变声」到底要多少空间

---

## 一、一句话结论

**32 GB 是底线，64 GB 是舒适线，128 GB 完全没必要。**

而且有个关键点可能和你的直觉相反：**你的两个功能加起来，模型本身占用不到 100 MB。**

真正吃存储的是**操作系统**，不是 AI。详见下面。

---

## 二、四档技术路线，对应四档存储

你说的"AI语义理解"和"实时变声"各有几种做法，占用差 100 倍：

| 路线 | 你的两个功能怎么做 | 模型占用 | 全盘占用 |
|---|---|---|---|
| **A. 保底方案** ⭐推荐 | 关键词识别控灯 + DSP 变声 | **< 100 MB** | **约 9–15 GB** |
| **B. 进阶方案** | 完整语音识别控灯 + DSP 变声 | 0.3–1 GB | 约 10–16 GB |
| **C. 冲刺方案** | 完整语音识别 + 神经变声（RVC） | 1–2 GB | 约 11–19 GB |
| **D. 豪华方案** | 语音识别 + 小语言模型（真语义理解）+ 神经变声 | 3–5 GB | 约 13–22 GB |

**结论：即使做 D，64 GB 也够。你完全不需要为存储花钱。**

---

## 三、逐项明细（带实测数字）

### 1. 操作系统 —— 唯一的大头

ROCK 5B+ 官方镜像的实测体积（来自 Radxa 官方构建仓库）：

| 文件 | 体积 |
|---|---|
| `rock-5b-plus_bookworm_kde_r7.output_512.img.xz`（**压缩**下载包） | **1.43 GB** |
| `rock-5b-plus_bookworm_kde_r7.rootfs.tar.xz`（压缩的根文件系统） | 1.41 GB |

解压安装后（含 KDE 桌面）大约 **5–8 GB**。加上系统更新和常用工具，实际占 **6–10 GB**。

> ⚠️ **一个值得知道的限制**：Radxa 官方对 5B+ **只提供 Debian KDE 桌面版镜像**，发布说明里明确写了——以前那些精简版/服务器版"不再提供，需要的用户请自行构建"。
> 也就是说**你没法通过换个精简镜像来省空间**（除非用 Armbian / DietPi 等第三方镜像，但对零基础不推荐折腾）。

### 2. Python 运行环境

| 组件 | 占用 |
|---|---|
| `python3` + pip | ~150 MB |
| `numpy` | ~40 MB |
| `sounddevice` + PortAudio | ~10 MB |
| `pyserial` | ~1 MB |
| `sherpa-onnx`（aarch64 预编译 wheel） | **4.2 MB** |
| `onnxruntime`（推理后端，随依赖安装） | ~50–150 MB |
| **小计** | **约 0.3–0.5 GB** |

### 3. AI 模型 —— 比你想象的**小得多**

#### 🔹 关键词识别（控灯用，推荐）

`sherpa-onnx` 官方 KWS 模型的**实测体积**（GitHub release 上的真实文件大小）：

| 模型 | 语言 | 体积 |
|---|---|---|
| `sherpa-onnx-kws-zipformer-wenetspeech-3.3M-2024-01-01` | 中文 | **32.7 MB** |
| └ 同上的 **mobile 版** | 中文 | ⭐ **15.3 MB** |
| `sherpa-onnx-kws-zipformer-zh-en-3M-2025-12-20` | 中英双语 | 32.9 MB |
| `sherpa-onnx-kws-zipformer-gigaspeech-3.3M` | 英文 | 17.6 MB |

**一个能听懂中文关键词的模型，压缩包只有 15–33 MB，解压后大约 30–70 MB。**

这就是你"AI 语义理解控灯"的全部模型成本。

#### 🔹 完整语音识别（如果要识别整句话）

| 类型 | 占用 |
|---|---|
| 小尺寸 streaming zipformer（中英） | ~50–200 MB |
| Paraformer-zh | ~230 MB |
| SenseVoice（多语种） | ~500–900 MB |

#### 🔹 实时变声

| 做法 | 占用 |
|---|---|
| **DSP 变声**（移调 / 机器人音 / 环形调制） | ⭐ **0 MB** |
| 神经变声（RVC 全套） | ~0.7–1.5 GB/音色 |

**这里是最容易被高估的地方**：DSP 变声（也就是我建议你先做的保底方案）**一个模型文件都不需要**，纯数学运算。你写的几十行 Python 就是全部。

神经变声（RVC）的构成大致是：
- `hubert_base.pt`（内容编码器）：约 300–400 MB ← 最大的一块
- `rmvpe.pt`（音高提取）：约 180 MB
- 生成器 `.pth`：约 55–110 MB／每个音色
- `.index` 检索文件：10–150 MB

> 以上 RVC 数字是经验值范围，不是实测；但它属于冲刺目标，不影响你的采购决策。

#### 🔹 如果真要上小语言模型（"理解"自然语言）

| 模型 | int8 量化后 |
|---|---|
| Qwen2.5-0.5B | ~0.5 GB |
| Qwen2.5-1.5B | ~1.5 GB |
| Qwen2.5-3B | ~3 GB |

**但控制个灯完全不需要 LLM。** 说"红色"就变红，关键词识别足够了——这也是我把它排在加分项而不是必做项的原因。

### 4. 其他

| 项目 | 占用 |
|---|---|
| 你的代码 + git | < 100 MB |
| 日志、缓存、临时文件 | 0.5–1 GB（会持续增长） |
| 桌面环境用户数据、浏览器缓存 | 1–2 GB |
| **建议预留的余量** | **20–30% 空闲** |

## 四、比容量更重要的三件事

### 1. 容量不是瓶颈，**速度**才是

模型加载后**常驻内存**，推理过程不再读盘。所以你用 microSD 还是 NVMe，**推理速度几乎没差别**，差别只在：

| 场景 | SD 卡（正品 A2） | NVMe |
|---|---|---|
| 开机 | 25–40 秒 | 12–20 秒 |
| 首次加载模型 | 1–5 秒 | 0.3–1 秒 |
| 编译 / apt 安装 | 慢，但能忍 | 舒服 |
| **推理速度** | **一样** | **一样** |

**所以 16GB 内存 + 正品 A2 microSD 对这个项目完全够用，NVMe 是锦上添花，不是必需。**

### 2. 一定要买正品 A2 卡

官方 FAQ 在"无限重启"的排查建议里明确提到：**"使用更快的 SD 卡"**。杂牌卡不只是慢，还可能直接启动失败。

**A2 比容量重要得多。** 64GB A2 就是甜点配置（约 ¥42）。

### 3. 别在板子上训练模型

如果你要自己训练一个音色（RVC 训练），**不要**在板子上做：
- 训练需要 CUDA GPU，板子没有
- 训练过程会产生几 GB 的中间特征文件和检查点
- 数据准备（10 分钟干净录音 ≈ 60 MB WAV，特征提取后几百 MB）

**做法**：在 PC 上训练 → 只把训练好的模型（~100 MB）拷到板子上。

---

## 五、最终建议

| 项目 | 建议 | 理由 |
|---|---|---|
| microSD | **64GB A2，正品**（¥42） | 装完系统还有 3–4 倍余量 |
| 16GB 内存 | 已够 | 所有模型加起来不到 2 GB，常驻内存绰绰有余 |
| NVMe SSD | **现阶段不要买** | 省下的 ¥120–150 花在麦克风、音箱、亚克力道具上收益高得多 |
| 128GB 卡 | 不必要 | 多花的钱换不来任何东西 |

**一句话：存储不是你这次要操心的问题，把预算花在"听得清、看得见"上。**

---

## 六、顺手几个省空间 / 保寿命的技巧

```bash
# 1. 清 apt 缓存（每次装完东西释放几百 MB）
sudo apt clean

# 2. 看一眼到底谁在占地方
sudo du -h --max-depth=1 / 2>/dev/null | sort -rh | head -20

# 3. 把日志限制一下（SD 卡最怕日志狂写）
sudo journalctl --vacuum-size=100M

# 4. 把 /tmp 挂到内存（少写盘 = 卡更耐用 + 更快）
#    在 /etc/fstab 加一行： tmpfs /tmp tmpfs defaults,noatime,size=512M 0 0
```

> **不要在 SD 卡上配大 swap。** 16GB 内存根本用不到，而 swap 会显著加速卡的老化。如果系统默认建了 swapfile，可以关掉。

> **保持 20–30% 空闲。** SD 卡写满之后性能会断崖式下跌，还会增加坏块风险。

# 附录：加上「真 AI 变声」（RVC）后，64GB 还够吗？

## 结论：够，而且很宽松

即使用最"重"的神经变声方案，**64 GB 也用不到三分之一**。32 GB 其实也够，只是余量没那么舒服。

**存储从来不是这件事的瓶颈。**

## 完整测算

| 项目 | 占用 |
|---|---|
| 操作系统（Debian KDE，官方唯一镜像） | 6–10 GB |
| Python 基础环境 + onnxruntime | 0.5–1 GB |
| sherpa-onnx + 中文 KWS 模型 | 0.05–0.1 GB |
| **RVC 的 Python 依赖** ⚠️ | **1.5–3 GB** |
| RVC 预训练组件（PyTorch 原版） | ~0.6 GB |
| ├ `hubert_base.pt`（内容编码器） | ~361 MB |
| ├ `rmvpe.pt`（音高提取） | ~181 MB |
| └ 其他辅助文件 | ~50 MB |
| 训练好的音色模型 `.pth` | 55–110 MB／个 |
| `.index` 检索文件 | 10–150 MB／个 |
| 转换后的 ONNX / RKNN 模型（如果做 NPU 部署） | 0.2–0.5 GB |
| 代码 + 日志 + 缓存 | 1–2 GB |
| **合计** | **约 11–18 GB** |

> ⚠️ **最容易低估的一块是"RVC 的 Python 依赖"**，不是模型。
> PyTorch（CPU 版）+ transformers 或 fairseq + librosa/numba + faiss-cpu + praat-parselmouth + torchaudio，这一套装下来轻松吃掉 **1.5–3 GB**。
> 大家总盯着"模型多大"，其实环境比模型大。

### 对比

| 存储 | 神经变声方案的余量 | 判断 |
|---|---|---|
| **32 GB** | 剩 ~14 GB | 够，但别再多装东西 |
| **64 GB** | 剩 ~46 GB | ⭐ **非常宽松** |
| 128 GB | 剩 ~110 GB | 纯浪费 |

## 但有四种情况会真的把空间吃掉

这几种都不是"模型大"，而是用法问题：

| 情况 | 额外占用 | 会不会发生在你身上 |
|---|---|---|
| 在板子上**训练**音色（提取特征 + 检查点） | +3–8 GB | ❌ 不可能——训练需要 CUDA GPU，板子没有。**必须在 PC 上训练** |
| 用 Docker 做 RKNN 转换 | +5–15 GB | ❌ 不会——`rknn-toolkit2` 只在 x86 Linux 上跑，装在笔记本里 |
| 从源码编译 onnxruntime / torch | +5–10 GB 构建目录 | ⚠️ 有可能，**务必用 pip 装预编译包**，别从源码编 |
| 囤几十个音色模型 + 数据集 | +2–5 GB | ⚠️ 有可能，但 64 GB 扛得住 |

**结论：只要不在板子上训练、不从源码编译，64 GB 稳稳够用。**

## 真正该担心的不是存储，是这四件事

| # | 风险 | 说明 |
|---|---|---|
| 1 | **模型转换工作量** 🔴 最大 | PyTorch → ONNX → RKNN。RVC 生成器含自定义算子和动态 shape，RKNN 支持有限，可能要改结构、固定输入长度。**这是几周级别的工程量，不是几天** |
| 2 | **必须有一台 x86 Linux** | `rknn-toolkit2` 只在 x86_64 Linux 上跑 → 你的 Windows 笔记本要装 WSL2 或 Ubuntu |
| 3 | **实时延迟** | 整条链路 = HuBERT 特征提取 → 检索 → 生成器 → 声码器。6 TOPS 算力够，但要在每个音频块预算内跑完，需要精细优化。**我找了半天，没找到公开成熟的"RK3588 实时 RVC"项目——这个"找不到"本身就是一个强信号** |
| 4 | **依赖版本地狱** | RVC 依赖 fairseq（出了名难装）或特定版本的 transformers/torch/numpy。**在 ARM64 上装这一套尤其痛苦** |

## ⭐ 一个折中方案：把"实时 AI 变声"换成"离线 AI 变声"

这是我很推荐的做法，能让你既保住"AI 变声"这个卖点，又不用赌实时性：

| | 实时变声 | AI 变声 |
|---|---|---|
| **实现** | DSP（移调 / 机器人音） | RVC **离线**转换 |
| **交互** | 对着麦说话，立刻听到变化 | 录 10 秒 → 转成另一个音色 → 播放 |
| **跑在哪** | 板子（CPU，毫秒级） | 板子（CPU 跑原版 PyTorch，30–60 秒）**或笔记本** |
| **要不要 RKNN 转换** | 不需要 | ⭐ **不需要** |
| **难度** | ★★ | ★★★ |
| **存储影响** | 0 | 和上面算的一样（11–18 GB） |

**关键洞察**：离线转换对速度没要求，所以**根本不需要做 RKNN 转换**——直接在板子上装 PyTorch CPU 版（aarch64 有现成 wheel）跑原版 RVC 推理就行，慢一点无所谓。

**难度直接降一个数量级**，而演示效果依然震撼：评委说一句话 → 你把它变成另一个人的声音放出来。

### 演示脚本可以这样设计

1. 对着麦说话 → 灯带随音量律动（**实时**）
2. 按一下按钮 → 声音变成机器人音（**实时 DSP**）
3. 再按一下 → 播放刚才那句话的"AI 版"（**离线 RVC，另一个音色**）
4. 说"蓝色" → 灯带变蓝（**实时语音识别**）

四层效果，前三个几乎零风险。

## 给你的一句话建议

**存储不用为神经变声多花一分钱，64 GB 绰绰有余。**
**但时间预算要重算：实时 AI 变声是独立的几周项目，不是"再做一周"。**

所以还是按原计划——
- **闸门 2（11/1）**：AI 语音控灯跑通、演示稳了，再考虑动神经变声
- 想动的话，**先做离线版**，别碰实时版
- 实时版留到 11/8 之后如果还有余力再说

# 附录二：microSD 该买什么速度等级？

## 一句话答案

**认准 `A2` + `U3` + `V30`（卡面上同时印着这三个标记）。低于这个会难受，高于这个纯浪费钱。**

## 先看懂卡面上那堆标记

一张 microSD 卡上通常有 4 套并存的等级标记，各管一件事：

| 标记体系 | 写法 | 含义 | 对你的重要性 |
|---|---|---|---|
| **应用性能等级**<br>Application Performance Class | **A1 / A2** | **随机**读写 IOPS：<br>A1 = 1500 读 / 500 写 IOPS<br>A2 = 4000 读 / 2000 写 IOPS | ⭐⭐⭐ **最重要** |
| UHS 速度等级 | U1 / U3 | 最低顺序写 10 / 30 MB/s | ⭐⭐ |
| 视频速度等级 | V6/V10/**V30**/V60/V90 | **持续**顺序写 30/60/90 MB/s | ⭐⭐（V30 足够） |
| 原始速度等级 | Class 2/4/6/**10** | 最低顺序写 10 MB/s | ⭐（老旧标准） |

**核心认知：把系统装在 SD 卡上时，决定"卡不卡"的是随机 I/O，不是顺序速度。**

引用 Radxa 论坛里 SBC 存储测试圈公认权威 tkaiser 的原话：

> **"Use case first! With the rootfs on an SD card almost all that matters is random I/O while sequential transfer speeds are (close to) irrelevant."**
> （先想用途！当根文件系统在 SD 卡上时，几乎只有随机 I/O 重要，顺序传输速度基本无关。）

## A1 V30 vs A2 V30：差别到底在哪

**先说结论：V30 部分完全一样，差别 100% 在随机 I/O。**

`V30` 是视频速度等级（保证持续顺序写 ≥30 MB/s），`A1/A2` 是应用性能等级（规定随机 IOPS）。两个维度互相独立——所以"V30"在两张卡上是同一个数字，唯一变量是 A1 还是 A2。

### SD 协会的官方规定

| 等级 | 最小随机读（4K） | 最小随机写（4K） | 最小持续顺序写 | 免费换算成 MB/s |
|---|---|---|---|---|
| **A1** | 1500 IOPS | 500 IOPS | 10 MB/s | 读 **6 MB/s** / 写 **2 MB/s** |
| **A2** | 4000 IOPS | 2000 IOPS | 10 MB/s | 读 **16 MB/s** / 写 **8 MB/s** |
| 倍数 | **2.7×** | **4×** | 1×（V30 补到 30） | |

注意最后一列：**A1 和 A2 的最小持续顺序写要求是一样的（都是 10 MB/s）**。也就是说 A2 多花的钱买的完全是随机性能——恰好就是跑系统最需要的那一项。

### 但 A2 的 4 倍不是白给的

A2 要达到那个指标，卡和**主机**要配合两个额外机制：

1. **Command Queuing（命令队列）**——让主机一次排多个命令
2. **Write Caching（写缓存）**——卡上有缓存，需要主机的专门命令来刷新

**这两个机制主机不支持，A2 就发挥不出来。** 而这块板子恰好就不太支持（Rockchip 的 5.10 内核只为 eMMC 启用了 command queuing，SD 卡没有；写缓存是主线 5.15 才有的）。

### 好消息：A2 永远不会比 A1 更差

这是 Armbian 官方文档的原话，可以直接放心：

> **"A2 is not slower or less supported than A1 on Armbian — where an A2 card's command-queuing feature isn't used it simply behaves like an A1, never worse. Either rating is fine; A2 is the safer target when buying new."**
> （A2 不会比 A1 更慢或兼容性更差——当 A2 卡的命令队列特性没被使用时，它就只是表现得像 A1，绝不会更糟。两个等级都行，买新的时 A2 是更稳妥的选择。）

所以在你这块板子上：**A2 卡大概率只能跑出接近 A1 的水平，但不会低于它。** 4 倍的纸面差距被压缩，但绝不会变成负数。

> ⚠️ 唯一要注意的反面情况：A2 只是"不更差"，不是"一定更好"。论坛里 tkaiser 实测过**老的 A1 卡跑赢新的 A2 卡**——因为不同批次、不同控制器差异很大。**A 等级是筛选门槛，不是性能保证。**

### 那到底买哪个？

| 情况 | 建议 |
|---|---|
| A2 V30 和 A1 V30 **价格差不多**（64GB 常见差价 ¥10–20） | ⭐ **直接买 A2 V30**——不会更差，且通常是更好的控制器 |
| A1 V30 **明显便宜**（差 30% 以上） | A1 V30 完全可用，在这块板子上体感差距不大 |
| 卡上**没印 A 等级** | ❌ 别买。这类卡随机性能可能只有 A1 的几分之一，是"系统卡顿"的常见元凶 |
| V60 / V90 | ❌ 别买（接口吃不到，纯浪费） |

**一句话：优先 A2 V30；A1 V30 是合格底线；没有 A 等级的不要碰。**

> 顺带一提，Armbian 官方文档开篇就是这句话，很值得记住：
> **"In over 95% of 'Armbian won't boot' or stability reports, the cause is the SD card or the power supply — not the board and not the image."**
> （超过 95% 的"板子起不来"报告，原因都是 SD 卡或电源，不是板子也不是镜像。）
> 你的两块变量正好都是"便宜方案"（杂牌卡 + HD-05 电源），所以前面那套验真流程和供电纪律别省。

## A1 和 A2 的真实性能差距（实测数据）

规范上的差距（2.7× / 4×）和实际能拿到的差距是两回事。下面是 SBC 存储测试圈公认权威 tkaiser 用 iozone 在 NanoPi M4（已开 UHS/SDR104）上做的横评，同一品牌、同一时期：

| 项目 | **SanDisk Ultra A1**<br>(2017-09) | **SanDisk Extreme A1**<br>(2017-10) | **SanDisk Extreme Pro A2**<br>(2018-08) |
|---|---|---|---|
| 4K 随机读 IOPS | **2867** | **3201** | **1766** |
| 4K 随机写 IOPS | 787 | **1480** | 732 |
| 16K 随机写 IOPS | 516 | 769 | 427 |
| 顺序读 MB/s | 66 | 66 | 65 |
| 顺序写 MB/s | 18 | **59** | 50 |
| 开机耗时 (s) | **14.2** | 16.2 | 17.0 |
| 装桌面环境 (s) | 207 | **161** | 190 |
| 删除 150 个包 (s) | 31 | **28** | 36 |

**结果非常反直觉：那张 A2 卡比两张 A1 卡都慢**，连最便宜的 Ultra A1 都比它快（除了顺序写）。

> 原作者的结论：
> **"due to lacking A2 host support (drivers) at least SanDisk A2 rated cards are outperformed by A1 cards from the same company (even the cheap Ultra A1 is faster everywhere except sequential write performance)"**

### 为什么？两个关键机制

1. **A2 的高性能依赖主机配合。** A2 靠 **Command Queuing + Cache** 才能跑到 4000/2000 IOPS，而这两个功能**必须主机（驱动）先开启**。主机不支持时，A2 卡只能退回传统模式运行。
2. **那块 A2 卡"刚好只达到 A1 的规格"** —— 原话是 "They barely meet A1 specs (the 1500/500 read/write IOPS)"。它 4K 读 1766 IOPS（A1 下限 1500 ✅，A2 下限 4000 ❌）。

### 所以正确的理解是

| 说法 | 对不对 |
|---|---|
| "A2 一定比 A1 快 4 倍" | ❌ 错。只在**主机完整支持 CQ + Cache** 时才可能接近 |
| "A2 架构上比 A1 更差" | ❌ 错。不用那两个功能时，它就按普通模式跑 |
| **"A 等级只是下限，不代表实际水平"** | ✅ **这才是关键** |
| **"一张优秀的 A1 卡能跑赢一张平庸的 A2 卡"** | ✅ 实测证实 |

**A1/A2 标签只保证"不低于 X"，不告诉你"到底有多高"。** 2017 年那批 A1 卡实测能跑到规格的 2–6 倍，而 2018 年那张 A2 只勉强过 A1 线。

### 放到你这块板子上：差距被压缩了

ROCK 5B+ 用的是 Rockchip **5.10 BSP 内核**，其中 command queuing **只为 eMMC 启用，SD 卡没有**（写缓存更是主线 5.15 才进）。也就是说：

> **A2 的加速机制在你的板子上基本用不上。A2 卡大概率只能跑出接近 A1 的水平。**

这就是我建议你「预算紧就买 A1」的根据——**不是 A1 更好，而是你多花的钱买不到那 4 倍。**

### ⭐ 真正该在意的差距：好卡 vs 烂卡，差 6 倍以上

同一份测试里的"普通卡"（从旧相机里翻出来的一张 Intenso Class 4 4GB）：

| | 优秀 A1 卡 | 普通杂牌/旧相机卡 | 差距 |
|---|---|---|---|
| 4K 随机写 IOPS | 787–1480 | **33** | **24–45×** |
| 16K 随机写 IOPS | 516–769 | **2** | **258–385×** |
| 装桌面环境耗时 | 161–207 s | **1070 s** | **5–6.6×** |
| 删除 150 个包 | 28–31 s | **149 s** | **~5×** |

**A1 和 A2 之间的差距（<20%）远小于"好卡和烂卡"之间的差距（5 倍以上）。**

> ⚠️ **这条也修正了我之前"先翻抽屉找旧卡"的建议**：可以翻，但**必须先测**。很多旧相机卡/杂牌的随机写只有 33 IOPS，装个环境要 17 分钟，会让你怀疑板子坏了。**测出来 4K 随机写低于约 200 IOPS 的卡，只能当备用盘，不能当系统盘。**

### 怎么测你自己的卡

```bash
sudo apt install -y fio
# 4K 随机写（最关键的一项）
fio --randrepeat=1 --ioengine=libaio --direct=1 --gtod_reduce=1 \
    --name=rw --filename=/home/radxa/t --bs=4k --iodepth=32 \
    --size=128M --readwrite=randwrite
# 4K 随机读
fio --randrepeat=1 --ioengine=libaio --direct=1 --gtod_reduce=1 \
    --name=rr --filename=/home/radxa/t --bs=4k --iodepth=32 \
    --size=128M --readwrite=randread
```

| 4K 随机写 IOPS | 判定 |
|---|---|
| < 200 | ❌ 烂卡（旧相机卡级别），只能当备用 |
| 300–600 | 🟡 勉强能用 |
| 700–1500 | ✅ 好卡（优质 A1 / A2 水平） |

## 这块板子的实测数据（很有说服力）

Radxa 论坛有人用 iozone 在 ROCK 5B 上实测了一张 **UHS SDR104** 卡（即跑在最高档的卡），我把原始 KB/s 换算成了 MB/s：

| 块大小 | 顺序写 | 顺序读 | **随机读** | **随机写** |
|---|---|---|---|---|
| **4 KB** | 5.8 MB/s | 18 MB/s | **12.6 MB/s** | **5.1 MB/s** |
| 16 KB | 21.6 MB/s | 44.6 MB/s | 35 MB/s | 21 MB/s |
| 512 KB | 62.9 MB/s | 79.7 MB/s | 79.4 MB/s | 63.3 MB/s |
| 16 MB | 76.5 MB/s | 87.6 MB/s | 87.1 MB/s | 72.6 MB/s |

**重点看第一行**：
- 大块顺序读写能到 **~87 / ~77 MB/s**，看着很漂亮
- 但 **4K 随机写只有 ~5 MB/s** —— 这才是你平时"卡不卡"的真实来源

所以：
- `apt install` 一个包等半天 → 正常，这就是 4K 随机写的极限
- Python 启动慢 → 同上
- **但推理速度和这些毫无关系**（模型加载后就在内存里）

> **参照**：同一块板子上 eMMC 约 370 MB/s、NVMe 顺序 650 MB/s 以上。SD 是最慢的，但**只影响开机和装软件，不影响推理**。

## 为什么 A2 的好处在这块板子上要打折扣

论坛里有人指出一个细节，知道了能避免期待落空：

> Rockchip 提供的 5.10 内核**只为 eMMC 启用了 command queuing，SD 卡没有**；而 A2 卡充分发挥性能所需的 **write caching 是主线 5.15 才实现的**，不在 5.10 里。

tkaiser 另提到：

> **"at least in the beginning Radxa shipped their OS images with some serious downclocking for reasons unknown to me."**
> （至少早期 Radxa 的镜像对 SD 时钟做了明显降频，原因不明。）

**结论：板子的 SD 接口本身就是瓶颈。** 所以：
- ✅ 买 A2 是对的（仍是能买到的最好的）
- ❌ 但**买 V60 / V90 完全没意义**——接口吃不到，纯浪费钱
- ⚠️ 如果卡跑不出上表数字，不一定是卡的问题，可能是设备树的时钟设置

## ⭐ 比"挑哪个牌子"重要得多：立刻验真

论坛反复强调：**假卡/白片是这个领域的大问题**，而且

> **"product rankings of this sort are questionable by definition since even if the honest reviewer tested e.g. brand A to be the best, the person reading the review might end up buying a *fake* A product."**

假卡通常**写入速度只有真卡的四分之一**——正好命中你最在意的随机写。

所以正确策略不是"买最好的牌子"，而是：
1. **在自营/官方旗舰店买**（有"无理由退货"）
2. **到货后立刻验真**——这步不能省

### 到货后 10 分钟验收流程

```bash
sudo apt install -y f3

# 第 1 步：快速探针（⚠️ 会破坏卡上数据，所以必须在烧系统之前做！）
sudo f3probe --destructive --time-ops /dev/mmcblk1
#   报 "good" → 继续；报错或容量不符 → 立刻退货，别犹豫
```

烧完系统、能进系统后，再做第 2、3 步：

```bash
# 第 2 步：真实容量 + 真实读写速度（写满再读回）
sudo f3write /media/radxa/<你的挂载点>
sudo f3read  /media/radxa/<你的挂载点>

# 第 3 步：随机写到底多少（体感的关键指标）
sudo apt install -y fio
fio --randrepeat=1 --ioengine=libaio --direct=1 --gtod_reduce=1 \
    --name=sdtest --filename=/home/radxa/sdtest --bs=4k \
    --iodepth=32 --size=128M --readwrite=randwrite
```

**参照值**：4K 随机写应在 **3–6 MB/s** 上下。如果测出来不到 1.5 MB/s，那基本就是假卡或严重降频。

## 别让卡被日志写死

论坛另一条重要提醒：

> **"with 'Linux defaults' ... the card will be simply logged to death. The problem is called 'Write Amplification'."**

结合上面"4K 随机写只有 5 MB/s"的事实——**系统日志的持续小写入正是最伤卡、也最拖慢系统的东西**。三件事就能显著改善：

```bash
# 1. 限制日志体积
sudo journalctl --vacuum-size=100M
#    永久生效：编辑 /etc/systemd/journald.conf，设 SystemMaxUse=100M

# 2. 减少 atime 写入：/etc/fstab 的根分区选项里加 noatime
# 3. 不要配大 swap（16GB 内存用不到，swap 会显著加速卡老化）
```

### Extreme 和 Extreme PRO 差多少？

| | **Extreme** | **Extreme PRO** |
|---|---|---|
| 等级 | A2 / U3 / V30 / C10 | A2 / U3 / V30 / C10 |
| 64GB 标称读 | 170 MB/s | **200 MB/s** |

**但在你这块板子上，这个差距约等于 0。** 两个原因：

1. **那些 170 / 200 MB/s 是"需要闪迪专用读卡器（DDR200 / QuickFlow）"才能达到的数字。** 标准 UHS-I 接口上限是 **104 MB/s**，而 ROCK 5B+ 实测顺序读约 **87 MB/s**——两张卡都会被卡在同一个地方。

**结论：当系统盘用，Extreme 就够，Extreme PRO 多花的钱买不到你能用到的东西。**

> 什么时候才值得上 Extreme PRO：你要把这张卡插到**相机 / 无人机**上拍高码率视频，或者需要它更强的持续写能力——那才是它的设计场景，不是 SBC 系统盘。

### 把"A 等级不可靠"这个风险转嫁给渠道

**京东自营支持七天无理由退货**——这就是你的保险：

1. 下单（自营）
2. 到货 → 先 `f3probe` 验真
3. 装上系统 → 跑 `fio` 测 4K 随机写
4. **测出来 < 200 IOPS 就直接退换**，别不好意思

**这比纠结型号有用得多**，因为 A 等级只保证下限，实际水平只能测出来。

> **关于抽屉里的旧卡**：可以翻，但**必须先测**。旧的相机卡/杂牌随机写可能只有 33 IOPS（装个环境 17 分钟）。4K 随机写低于约 200 IOPS 的只能当备用盘。

### ⚠️ 另一类要小心的卡：品牌授权贴牌卡

飞利浦（PHILIPS）、惠普、柯达、华硕等**不是存储厂商**的品牌，也在卖 microSD 卡。这类卡的特点是**明显比同规格一线品牌便宜**。

**为什么便宜？因为这是品牌授权生意。**

公开工商资料显示，这类品牌与"品牌授权方"的合作自 2009 年起就是**「经销授权 + 委托生产」**模式——品牌方只出租 logo，产品由第三方代工。媒体也报道过飞利浦品牌因过度授权而"从『皇家』走向『山寨』"（[新浪科技 2023](https://finance.sina.com.cn/tech/roll/2023-02-27/doc-imyicmyv8053118.shtml)）。

**这意味着：**品牌不告诉你任何关于闪存颗粒、主控和固件的信息。你付的钱买的是一个熟悉的 logo。

**对你的场景还有一个额外不利因素：**这类卡在电商上基本都定位成**「行车记录仪 / 安防监控 / 运动相机」专用**（例如京东在售的飞利浦 16GB U3 V30「行车记录仪&安防监控专用」、128GB A2 V30 U3「大疆/行车记录仪/无人机/监控」）。

而行车记录仪的设计目标是**长时间持续顺序写**——**这恰好和你的需求相反**。你的系统盘需要的是**随机 I/O**（我们前面已经用实测数据证明：决定 SBC 体感的是 4K 随机读写，顺序速度几乎无关）。

**顺带一提**：亚马逊上飞利浦那款标 A1/V30/U3 的 "Ultra Pro" 128GB，用户评价里对可靠性的反馈是两极分化的。

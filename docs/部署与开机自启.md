## 2. systemd 服务

### 2.1 服务定义要点

```ini
[Unit]
Description=kskbl 会听会变声的智能终端
After=sound.target network.target
Wants=sound.target

[Service]
Type=simple
User=radxa
Group=radxa
WorkingDirectory=/home/radxa/proj/kskbl

# USB 声卡和 SPI/GPIO 需要一点时间就绪
ExecStartPre=/bin/sleep 8

ExecStart=/home/radxa/proj/venv/bin/python -u src/kskbl/app.py \
    --trigger usb \
    --usb-id 0d8c:0014 \
    --gap 3 \
    --duration 30 \
    --silence-stop 0 \
    --noise-margin 15 \
    --speech-floor -35 \
    --mic-gain 28 \
    --voice wawa

Restart=always
RestartSec=5
StandardOutput=journal
StandardError=journal
SyslogIdentifier=kskbl

TimeoutStopSec=15
KillSignal=SIGINT

[Install]
WantedBy=multi-user.target
```

### 2.2 为什么 `ExecStartPre=/bin/sleep 8`

USB 声卡是热插拔设备，开机的头几秒可能还没枚举完。等 8 秒能避免第一轮失败。

即使还是太早，`Restart=always` + `RestartSec=5` 会自动重试，最终能起来。

### 2.3 为什么 `KillSignal=SIGINT`

程序的 `run()` 里有 `except KeyboardInterrupt` 和 `finally: self.close()` —— 用 SIGINT 能让它**正常关屏幕、关模型**，而不是被硬杀。

### 2.4 用户组

`User=radxa` 会继承该用户的附加组：`gpio`、`spidev`、`audio`、`input`、`dialout` 等。
这些是访问屏幕（SPI/GPIO）、声卡、耳机插孔事件设备必需的。

## 3. ⚠️ 免密关机（sudoers）

### 3.1 只授权两个命令

```
Cmnd_Alias KSKBL_POWEROFF = /sbin/poweroff, /usr/sbin/poweroff, \
                            /bin/systemctl poweroff, /usr/bin/systemctl poweroff

radxa ALL=(root) NOPASSWD: KSKBL_POWEROFF
```

**⚠️ 关键：`systemctl` 只允许 `poweroff` 这一个子命令。**

如果把整个 `/bin/systemctl` 开放成 root，等价于给了**完整 root 权限** —— 可以起停任意服务、改任意配置、读任意文件。

### 3.2 为什么必须先校验语法

sudoers 写坏了会**把 sudo 弄瘫**，那样连 SSH 都进不来（`sudo` 报错、无法提权）。

所以 `install_service.sh` 的做法是：

```bash
tmp=$(mktemp)
cat "$SUDOERS_SRC" > "$tmp"
if ! /usr/sbin/visudo -c -f "$tmp" >/dev/null 2>&1; then
    echo "❌ sudoers 语法校验失败，已放弃安装" >&2
    rm -f "$tmp"
    return
fi
install -m 440 -o root -g root "$tmp" /etc/sudoers.d/kskbl-shutdown
```

**先写临时文件、用 `visudo -c` 校验、通过了才写入正式位置。**

> `visudo` 在 `/usr/sbin`，普通用户 PATH 里可能没有，所以脚本用了绝对路径兜底。

### 3.3 权限要求

```
-r--r----- 1 root root /etc/sudoers.d/kskbl-shutdown
```

**必须是 0440、root:root**，否则 sudo 会拒绝加载。

## 4. ⚠️ 最容易踩的坑：改完代码必须重启服务

**这个坑踩过四次。**

```bash
# 你改了代码、也 scp 到板子了
scp src/kskbl/app.py radxa@板子:/home/radxa/proj/kskbl/src/kskbl/

# 然后你去测 —— 看到的还是旧行为！
```

**原因**：systemd 里的 Python 进程加载代码后**不会自动重载**，必须重启服务。

### 4.1 怎么确认跑的是不是最新代码

程序启动横幅会打印代码修改时间（这是为此专门加的）：

```
  代码版本：app.py 修改于 2026-11-13 13:18:02
```

和下面这个一比就知道：

```bash
systemctl show -p ActiveEnterTimestamp kskbl --value
```

**启动时间晚于代码时间 = 跑的是新代码。**

### 4.2 `apply.sh` 会帮你自动核对

```bash
sudo bash deploy/apply.sh
```

输出最后会明确告诉你：

```
  服务实际运行: 代码版本：app.py 修改于 2026-11-13 13:18:02
  代码文件时间: 2026-11-13 13:18:02
  ✅ 版本一致，新代码已生效
```

### 4.3 `/etc` 里的是副本，不会自动同步

```
你改的：  ~/proj/kskbl/deploy/kskbl.service
系统用的：/etc/systemd/system/kskbl.service
```

**只改 `deploy/` 那份不生效** —— 必须 `install`（复制到 `/etc`）+ `daemon-reload` + `restart`。

`install_service.sh` 和 `apply.sh` 都做了这三步。

## 5. 常用命令

```bash
# 一键部署（推荐，带版本校验）
sudo bash deploy/apply.sh

# 安装并启用开机自启
sudo bash deploy/install_service.sh install

# 卸载（含删掉免密关机规则）
sudo bash deploy/install_service.sh uninstall

# 只重启
sudo systemctl restart kskbl

# 看状态
systemctl status kskbl

# 实时日志
journalctl -u kskbl -f

# 本次开机的全部日志
journalctl -u kskbl -b
```

## 7. 其他踩过的坑

### 7.1 音色资产不能放 `/tmp`

音色资产（`~/proj/voices/<音色名>/`）**必须放持久目录**。

曾经放在 `/tmp/reg_manbo2/`，隔天再跑就报「曼波资产缺失」—— 系统的 `systemd-tmpfiles` 清理把整个目录删了。

### 7.2 WiFi 省电导致 SSH 不稳

```bash
# 查
iw dev wlP2p33s0 get power_save

# 关（重启后失效，需要每次开机后再执行）
sudo iw dev wlP2p33s0 set power_save off
```

### 7.3 `pkill -f` 会杀掉自己

```bash
# ❌ 危险：命令行里出现相同字面量，会把执行这条命令的 shell 也杀掉
pkill -f "tools/foo.py"

# ✅ 安全：用方括号技巧，或直接按 PID 杀
pkill -f "tools/foo[.]py"
```

### 7.4 屏幕的 GPIO 会被占住

如果程序异常退出没释放 `gpiochip4 line 20`（DC）/ `gpiochip3 line 4`（RES），再启动会报：

```
OSError: [Errno 16] Device or resource busy
```

排查：

```bash
ps -eo pid,args | grep -e kskbl -e st7789
gpioinfo gpiochip4 | grep PIN_18
```
